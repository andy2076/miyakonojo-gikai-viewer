# 定例会を1回追加する手順

質問カード（議員別の一般質問）を1定例会分追加するときの流れ。
令和8年第2〜4回定例会を追加したときの手順をそのまま残している。

---

## 1. 一般質問概要書PDFを取得する

一覧ページ: <https://www.city.miyakonojo.miyazaki.jp/site/gikai/70993.html>

このページの記事本文に定例会ごとのPDFリンクが並んでいる。
`a[href$=".pdf"]` を拾えば取得できる（リンクテキストに「一般質問概要書　令和8年9月定例会」のように会期名が入っている）。

```bash
curl -s "https://www.city.miyakonojo.miyazaki.jp/site/gikai/70993.html" \
  | grep -oE '<a[^>]+href="([^"]*\.pdf)"[^>]*>[^<]*</a>'
```

PDFの実体は `https://www.city.miyakonojo.miyazaki.jp/uploaded/attachment/<番号>.pdf`。

テキスト化は `pdftotext -layout <file>.pdf <file>.txt` でよい。
概要書の構造は次のとおり。

- 冒頭に「一般質問発言順番」の表（日付・開始時間・順番・氏名・会派）
- 以降に `発言順番N 氏名（会派）` の見出しごとに
  - 大項目 … 行頭の全角数字（`１ ○○について`）
  - 小項目 … 行頭の `（１）`

## 2. 構造化JSONを作る

`mieru-gikai-r8.json` と同じ形にまとめる。

```jsonc
{
  "generated_at": "2026-09-10",
  "sessions": [
    {
      "id": "r8-2",
      "name": "令和8年第2回定例会（3月）",
      "year": "令和8年",
      "source_pdf": "https://www.city.miyakonojo.miyazaki.jp/uploaded/attachment/44454.pdf",
      "questioner_count": 16,
      "questions": [
        {
          "order": 1,
          "date": "2026-03-05",
          "time": "10:00",
          "member": "田下勝利",       // 姓名の間に空白を入れない
          "party": "立憲民主",         // 概要書の表記をそのまま
          "topics": [
            { "no": 1, "title": "…について", "field": "高齢者福祉", "items": ["…について", "…について"] }
          ]
        }
      ]
    }
  ]
}
```

- `field` は `lib/field-categories.ts` の12分野から選ぶ。
- **議員名・会派は必ず原本PDFと突き合わせる。** 会派は同一年度内でも変わることがある
  （例: 徳留八郎は令和8年に 自民党市民の会 → 無会派 → 創生 と3回とも異なる）。
- 大項目数・小項目数は PDF の見出し数と一致することを確認する。

## 3. 答弁（AI要約）を作る

答弁は **都城市議会 会議録検索システム** から取る。

- 入口: <http://www.kensakusystem.jp/miyakonojo/index.html>
- 「会議録の閲覧」→ 年 → 会期 → 日付（`R080305A` のようなファイル名）
- 1日分の全文は `GetPerson.exe` に POST すると一括で落とせる
  （`r_Speakers.exe` の `downloadPos` を全部送る。文字コードは Shift_JIS）

会議録は **会期終了から数か月遅れて公開される**。公開されていない会期は答弁なしで先に出す
（`data/都城市議会_令和8年第2回_答弁要約.json` のようなファイルを作らなければ、
ビルドスクリプトが自動的に「通告段階」の表示になる）。

答弁要約のファイルは `"議員名|大項目番号"` をキーに `{ question, answer }` を持つ。

## 4. 質問カードJSONに変換する

```bash
node scripts/build-r8-card-json.js
```

`data/都城市議会_令和8年第N回_質問カード.json` が出力される。
別の年度を追加するときは、このスクリプトの `SESSION_CONFIG` を書き足す（またはコピーして作る）。

出力される件数（議員数 / 大項目 / 小項目）が概要書PDFと一致することを必ず確認する。

## 5. DBへ投入する

```bash
npx tsx scripts/import-meeting-cards.ts data/都城市議会_令和8年第2回_質問カード.json
# 入れ直す場合（既存カードを全削除してから再投入）
npx tsx scripts/import-meeting-cards.ts data/都城市議会_令和8年第2回_質問カード.json --force
```

- `meetings` に会期が無ければ追加し、`question_cards` を `published = true` で投入する。
- 会議名は既存データに合わせて全角数字（`令和８年第２回定例会`）に変換して保存される。
- **同じ会期のカードが既にある場合は何も挿入せずに終了する**ので、誤って複数回叩いても件数は増えない。
  入れ替えたいときだけ `--force` を付ける。

## 6. 議員名の表記ゆれをチェックする

集計は `member_name` の文字列一致で行うため、表記が違うと同一人物が二重に数えられる。

```bash
npx tsx scripts/normalize-member-names.ts          # 確認だけ
npx tsx scripts/normalize-member-names.ts --apply  # 姓名の間の空白を除去
```

改選で議員名の表記そのものが変わった場合（漢字→ひらがな等）は機械的に判定できないため、
人物を同定したうえで `scripts/merge-member-aliases.ts` の `MEMBER_ALIASES` に追記して統合する。

```bash
npx tsx scripts/merge-member-aliases.ts          # 確認だけ
npx tsx scripts/merge-member-aliases.ts --apply  # 統合を実行
```

### 新しい議員名を投入する前の照合

新規に見える議員名でも、次のパターンで既存の議員と同一人物のことがある。
投入前に必ず既存の全議員名（`SELECT DISTINCT member_name FROM question_cards`）と突き合わせる。

- **姓名の間の空白**の有無（`川内 賢幸` / `川内賢幸`）
- **漢字↔ひらがな**の表記変更（`成合円美佳` → `成合まるみか`）。読みが一致するかで判断する
- **旧字体・異体字**（`﨑`/`崎`、`德`/`徳`、`髙`/`高`、`濵`/`浜`、`邉`/`辺`、`齋`/`斎` など）。
  `﨑`(U+FA11) などは Unicode 正規化（NFKC）では `崎` にならないので、変換表を用意して比較する

同姓は別人のこともあるため（`黒木優一` と `黒木善寿`、`杉村義秀` と `杉村ともえ`）、
最終判断は**会議録の「出席議員」名簿に両名が併記されているか**で行うのが確実。

## 7. 画面側の確認

年フィルタ・ランキング・議会一覧・「最新データ」の表記はすべてDBから動的に生成されるので、
コードのハードコード修正は不要。追加後に以下を確認する。

- トップの「最新データ」が新しい会期になっているか
- 「議会から探す」の年フィルタに新しい年が出るか
- 年度別ランキング（ジャンル / キーワード / 質問テーマ数 / 閲覧数）に新しい年が出るか
- 「分野から探す」の12分野から新会期のカードが引けるか
- キーワード検索で新会期のカードが引けるか

```bash
npm run dev -- --webpack   # ローカルの日本語パスではTurbopackがクラッシュするため --webpack を付ける
```

## 8. 会期中の定例会・会議録公開後の答弁追記

一般質問の日程が終わっていない会期でも、概要書PDFが出ていれば通告内容だけ先に公開できる。

例: 令和8年第4回定例会（9月）は 9月8日〜9月14日 が一般質問日で、
9月14日に発言順番20（畑中ゆう子）・21（徳留八郎）が残った状態で先に公開している。
概要書PDFには会期全体の通告が載っているため、**掲載内容は会期中でも完成している**（後から増えない）。

会議録が公開されたら、次の手順で答弁を追記する。

1. 会議録検索システムで対象会期が公開されたか確認する（手順3参照）
2. 全文を取得し、`data/都城市議会_令和N年第M回_答弁要約.json` を作る
   （キーは `"議員名|大項目番号"`、値は `{ question, answer }`）
3. `scripts/build-r8-card-json.js` の `SESSION_CONFIG` で該当会期の `qaKey` を
   `null` からその会期のIDに変え、`source` の「※会議録未公開のため答弁未収録」を外す
4. `node scripts/build-r8-card-json.js` で質問カードJSONを作り直す
5. **`--force` を付けて**入れ直す
   ```bash
   npx tsx scripts/import-meeting-cards.ts data/都城市議会_令和8年第4回_質問カード.json --force
   ```
6. 画面から「この会期の会議録はまだ公開されていません」のバナー・注記が消えることを確認する

表示の切り替えは `answer_point` が空かどうかだけで判定しているので、フラグの更新は要らない。
カード一覧のバナーはその会期のカードに答弁が1件でも入ると消え、
詳細画面の注記は答弁が入ったテーマから順に消える。

想定スケジュール（令和7年の実績から）: 会期終了のおよそ3〜6か月後に会議録が公開される。
令和8年第3回（6月）・第4回（9月）は本稿執筆時点（2026年9月10日）で未公開。

## 9. 可決トピック（任意）

可決事項まとめは別テーブル（`meeting_topics`）。未登録の会期では
「可決トピック」ボタンは自動的に非表示になる。登録する場合は
`scripts/import-topic-v2.ts` などを使う。
